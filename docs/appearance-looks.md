# Appearance components and looks

The default v0.9.0 Workbench opens the appearance editor through **Panels → Properties → Look**. It offers **Basic, Classic, Ink, Kit, Opal, Porcelain, and Toon** in alphabetical order, plus your saved looks. The older interface (`?workspaceLab=0`) retains **Appearance → Preset** and the **Style Studio** launcher. Tiles apply complete looks, including their colors and backgrounds. The **Style** and **Color scheme** menus are independent mixing controls: Style changes display geometry, material, lighting and contours while keeping colors; Color scheme changes atom, bond, orbital-default and background colors while keeping the style. The legacy sidebar selector also keeps colors. A tile is pressed only when both menus show its id; mixed combinations press no tile. Hover uses a muted border, while selection retains the accent border and keyboard focus adds an outer ring. Number keys are reserved for editing. Geometry and material remain independent: Kit connectors can use any material.

For example, select **Classic** as the Style and **Opal** as the Color scheme to combine Classic shading with Opal's colors. Clicking the Opal tile then restores the complete Opal combination, even if Opal is already the active Style. Both menus also expose saved appearances, so either component can be reused independently. Color schemes include the background's Follow UI theme setting; light colors and optical material tint/specular/emission properties remain part of the style. Each menu retains its selected recipe when individual settings are edited; a dot and reset button mark edits on that row. Each selection is one Appearance Undo step, preserves orbital overrides, and never computes deferred orbitals.

The Studio previews changes immediately on the loaded molecule. Its title bar can be dragged; the window stays open while interacting with the scene. Close or Escape keeps the current appearance, and Undo/Revert restores earlier settings. Opening, moving, and closing the Studio never changes coordinates, camera, layer selection, or computed grids. Window position and open state are transient. The sidebar shows the current look and keeps the rendering, visibility, atom/bond coloring, camera, scene, and scientific surface controls. Shared style controls in either location update the same state.

Basic uses the approved **Luminous** material on atoms, bonds, and orbital surfaces: roughness `0.72`, metalness `0.04`, clearcoat `1`, coat roughness `0.1`, reflectivity `0.62`, color fill `0.36`, and no environment reflections. Its geometry, colors, lighting, and shadows retain their original settings. Selecting Basic in either the preset or material menu restores this shared recipe. Every curated preset now uses one material throughout.

Classic, Porcelain, Ink, and Opal retain the standalone Style Lab's camera-relative key/fill/rim lights, light directions, studio environment reflections, display radii, and material response. Classic uses smooth Phong shading without tone mapping; the other studio looks use ACES. All built-in presets enable shadows by default, including Basic at startup and the experimental looks. The Shadows switch and saved looks/sessions retain the user's choice to disable them. Opal retains the Lab's pearlescence thickness range. Transparent surfaces and depth of field use an HDR intermediate target when supported, preserving highlight values before the final tone mapping pass.

Classic defaults to atom scale **1.00**, metal scale **1.15**, and bond radius **0.110**. Its separate color scheme includes **National (red + / navy −)** orbital colors. These proportions are editable under Geometry; global color defaults are editable under Colors, and individual orbital overrides under Object/Surfaces.

Nocturne and Atelier remain experimental candidates in the [real-renderer comparison](experiments/style-lab/compare.html). The comparison supports methane, pyridine, metal coordination, and orbital lobes. **Materials only** holds the reference geometry, palette, background, and lighting fixed. Each preview opens the actual VibeMol editor. Study previews skip normal autosave, startup defaults, and workspace recovery; explicit saves and exports remain available.

## Surface palette names and compatibility

Surface palette labels state the positive and negative colors explicitly. **Tableau (blue + / red −)** replaces the former surface palette named Classic, with unchanged colors `#1f77b4` and `#d62728`. The Classic Look, global Color scheme entry, and material recipe retain their names and settings. Classic's National palette is red-positive/navy-negative; selecting a palette never changes Flip phase or orbital data.

`VibeMolLooks.normalizeSurfaceScheme` maps only the legacy surface id `classic` to `tableau`, before palette validation. Its readers are:

- `appearance-looks.js`: `settings` (and therefore `normalizeLook`/`importLook`), resolved `colors`, and legacy override comparison. Named browser libraries and startup defaults use `normalizeLook` through `looks-ui.js`.
- `scene-graph.js`: `createCubeAppearance`, generic cube/arithmetic layer creation, and scene restoration share `normalizeCubeColors`. Session hydration uses these same constructors.
- `session.js`: capture/hydration also normalize cached cube and per-MO appearance in source records. Complete sessions and IndexedDB recovery share this path. `session-format.js` validates structure without rejecting old palette ids; palette migration follows during hydration.
- `preset.js`: flattening flat/nested settings normalizes before setters, for strict and relaxed imports. The registered surface setter in `app.js` also normalizes before menu validation. Last-appearance autosave uses this preset reader; `src/prefs.js` only stores UI preferences.
- `app.js`: cached layer-state sanitization/persistence, appearance copying, palette rendering lookup, shared surface patches, default/override comparison, and control synchronization normalize surface ids.

Look and preset exports write the resolved positive/negative hex values alongside the canonical id. Session layers/source caches likewise retain explicit colors (including custom per-layer colors). Readers without the new palette can use these hex values as their color fallback.

`tests/e2e/surface_schemes.py` (also run by `looks.py`) checks the exact labels in both menus, unchanged Classic Look/material identities, strict/relaxed imports, session round-trips, named libraries, startup defaults, and last-appearance autosave. It compares rendered positive/negative material colors and verifies that changing Tableau to National leaves Flip phase off. Unit tests cover alias validation, explicit export values, arithmetic layers, and cached Molden state.

## Native editor

- **Geometry:** cylinders or Kit connectors, independent atom/metal scales, bond radius, Kit collar radius, and curved multiple bonds. Atom radii, Mesh detail, and Size multipliers expose the remaining shape settings. Per-element radii can be edited or reset to the covalent defaults. These affect displayed shapes, never molecular coordinates or topology.
- **Colors:** Studio Colors and sidebar Atoms/Bonds share the atom palette, element-color toggle/editor, By element / Uniform bond menu, and bond color swatch (Element tint in element mode). Uniform colors also apply to metal/coordination bonds and aromatic guides. Atoms contains the Standard / Luminous / Kit palette menu; explicit element-color swatches are used exactly. Orbital defaults exposes the global palette and custom positive/negative colors, including in Workbench. Scene contains Background and Follow UI theme. These controls update the independent Color scheme selector.
- **Material:** a section closed by default, using the same disclosure arrow as Geometry and Lighting. **Family** chooses Physical, Smooth (Phong), or Toon; **Recipe** lists that family's named materials, alphabetically, followed by saved personal materials. Main controls follow the family, with finer adjustments in Material channels and saving under Save material. Selections and edits apply to all atoms, bonds, and surfaces, across every loaded molecule and all hidden/deferred orbitals. There are no target tabs, linking controls, or separate Finish/Shading menus. Element and orbital phase colors remain distinct.
- **Gel:** replaces Glossy in the menu, using the original Gel recipe (roughness `0.15`, clearcoat `1`, coat roughness `0.02`, reflectivity `0.5`, color fill `0.15`, environment reflections `1.5`). Material selection preserves geometry, lighting, opacity, and scientific data. Old saved Glossy material descriptors and preset keys remain readable.
- **Opacity:** Studio **Surfaces → Opacity** edits the shared default saved with a look. Sidebar **Surfaces → Opacity** creates an explicit override on the selected orbital or every child of the focused Orbitals group, including hidden/deferred orbitals. Differing group values show Mixed. The slider and numeric value use the existing inspector styling and support Appearance Undo. They update surface/cloud materials without rebuilding geometry or changing the shared material recipe. Atoms and bonds are always opaque; Material has no opacity control. Legacy `molecule.opacity.atom` and `molecule.opacity.bond` settings are ignored on import and omitted from new looks/presets. Surface opacity remains portable in looks and sessions. Transient edit previews retain their visual cues.
- **Lighting & contours:** shadows, fog/depth (shared with sidebar Rendering), key/fill/rim/ambient strengths, key and rim directions, light colors, exposure, tone mapping, fixed-width or separate relative atom/bond contours, and highlight shells. Background and Follow UI theme now live under Colors → Scene. Background remains synchronized with Appearance → Scene → Background; both support grouped Undo, Modified, Revert and saving.
- **Retired effects:** the former Ink outlines and Blackbody coloring toggles and their rendering paths have been removed. Older preset/session flags are ignored on import and omitted from new exports. The curated Ink preset uses the standard material and contour system.
- **Orbital properties:** colors, isovalues, Auto-iso, visibility, phase, and surface/cloud mode retain their group/selected-orbital behavior. Every orbital uses the current look's surface finish, including future sources.

The editor reuses these existing components:

| Purpose | Existing implementation |
| --- | --- |
| Sections and disclosures | `vm-appearance-section`, `vm-section-label`, `inspectorSubsectionSummary` |
| Aligned fields | `vm-field-row`, `vm-field-label`, `vm-field-control` |
| Preset and material menus | `vm-select` |
| Numeric controls | `VmSlider`, `vm-slider__range`, `vm-slider__value`, `vm-mono` |
| Switches and colors | `vm-toggle`, `vm-color-swatch` |
| Menus and actions | `vm-select`, `vm-btn vm-btn--ghost vm-btn--sm`, `vm-popover__actions` |
| Status text | `vm-session-status` |

`looks-ui.css` provides the Studio layout, preview gallery, hidden-state, wrapping, and spacing rules. Look/material actions reuse the compact inspector button styling, including hover, disabled, and keyboard-focus states. Save/share disclosures use `vm-section-label`, and the current look name uses `vm-stat-label`. The editor follows the selected app font and theme without separate typography or color rules.

Material also exposes each Toon band's brightness, emission scale/mixing, and the pearlescence thickness interval. **Use surface finish everywhere** appears only for older saved appearances with a separate surface descriptor; new Basic does not need it. See the [appearance audit](appearance-audit.md) for the complete preset-to-control inventory.

## Saving and preservation

**Undo** restores the previous appearance settings and both recipe references, grouping a slider drag into one step. Molecular edit undo remains separate. The Style and Color scheme rows independently compare live settings against their referenced recipes. Each modified row shows the same dot and reset button as Object overrides. Its reset changes only that half; **Revert** restores the composed baseline without changing either reference. Both are disabled for an unmodified combination. Object overrides never flag a Look row. Built-ins cannot be overwritten.

The summary names the references: **Opal**, **Opal style · Classic colors**, or **Opal style · Custom colors** when one has no reference. It has no modified suffix. A tile remains pressed while its two references match, including after edits. Equal-looking user recipes retain their own names; the menus never infer identity from live values. Unlisted references, such as Nocturne or a session's retained user recipe, display a disabled option with the real name.

**Save as new** stores the full live combination and points both references at the new user look. **My looks → Choose saved look** and Import apply a complete saved combination, like a tile. The mixing menus apply only their respective halves. **Update saved** is enabled only for a modified pair referencing the same user look. Rename follows the id; deleting a referenced look clears only its matching references and keeps the rendered settings. A null reference has no baseline, modified flag, or reset. Save & share manages the referenced saved Style, or the saved Color scheme when the Style is built-in; its tooltips name that target.

**Set as default** captures the complete current combination. New sessions start with both references on that recipe. A mixed or edited combination becomes its own startup recipe; an updated user recipe does not silently replace an earlier default snapshot. **Use last appearance** instead restores the last settings and independent references.

**Save material** creates a reusable material swatch. Material files (`vibemol.material`, version 1) contain a name and complete descriptor, without geometry, palette, lighting, or opacity. Named materials can be updated, removed, exported, and imported as the shared material. Both libraries hold up to 50 entries; imports are limited to 128 KB. Storage failures leave the in-memory result usable and prompt export.

Look files retain the portable `vibemol.preset` envelope with `meta.lookVersion: 4`. Version 4 saves global surface defaults and excludes camera/depth-of-field settings. `appearance.rendering` version 3 stores the shared `material` descriptor and an optional `surfaceMaterial` descriptor for older saved appearances, alongside geometry, lighting, coloring, and effects. A missing or null `surfaceMaterial` uses the shared material. Older v3 looks retain their stored shared or paired materials until a new material or preset is explicitly applied. Standalone Export look files still use `appearance.look` to describe the exported recipe; importing adds it to My looks with a new id.

General presets, sessions/recovery, and last-appearance autosave store `appearance.references: {styleRef, colorsRef}`. Each reference is `{kind: 'builtin' | 'user', id}` or null. A `looks` array carries the original baselines of the referenced user recipes (at most two), so edited values do not become their own baselines and sessions work in a fresh browser. Live settings remain the rendering source of truth. Built-in baselines resolve by id; a recipe update can therefore mark an older file modified while retaining its saved rendering. `session-format.js` validates reference metadata before replacing the workspace. `src/prefs.js` remains limited to UI theme/font preferences.

Legacy settings without references migrate once on import, including strict/relaxed preset imports and last appearance. A recorded look id supplies Style; without one, only a unique style match supplies it. Matching colors prefer that Style id, then built-ins in declared order, then user looks ordered by name. Missing matches become null. This is the only path that infers references from settings; ordinary edits and synchronization never do. `styleEqual(a,b)` uses `equal(a,withColors(b,a))`, preserving the existing field partition. The combined baseline is `withColors(style.settings,colors.settings)`; a null half keeps its live values.

The three families group the existing materials without changing their rendering:

| Family | Named recipes | Main controls |
| --- | --- | --- |
| Physical | Basic (Luminous), Emissive, Gel, Matte, Metal, Opal, Porcelain | Roughness, metalness, clearcoat, reflections, pearlescence, highlight color |
| Smooth (Phong) | Classic, Kit | Shininess, highlight color |
| Toon | Ink, Toon | Band count and each band's brightness |

All families also expose Color fill and Tint. Material channels holds applicable secondary controls: highlight strength, coat roughness, reflectivity, fill scale/blend/source, and pearl thickness. Phong has no environment map in this renderer, so it does not offer the ineffective Reflections control. Parameters disabled by zero coat, zero fill, zero pearlescence, or full metalness remain stored but are hidden until applicable.

Switching family starts with **Basic**, **Classic**, or **Toon**, respectively, as one Appearance Undo step. The Recipe row's reset button restores the entire original material, including its family and any explicit older surface descriptor. Every visible built-in Look has an identically named recipe derived directly from its resolved settings in `appearance-looks.js`; choosing a Look, importing, undoing, or restoring a session updates both menus from the stored descriptor. Family and recipe names do not add persistence keys or replace the resolved settings. Personal materials appear under **My materials** within their family; import applies and selects the imported family automatically.

Choosing a material preserves the current Look's geometry, coloring, lighting, contours, and identity. All recipes use one shared finish. **Custom** is a disabled status entry for unmatched values. Recipe matching and Look Modified compare active shader settings with numeric tolerance; inactive parameters do not prevent manually matching a named recipe. Legacy vertex-emission overrides and explicit surface descriptors remain significant. Saving and Undo retain the full descriptor, including dormant values.

The four complementary finishes are Gel (smooth clearcoat and reflections), Matte (rough, uncoated diffuse shading), Metal (full metalness), and Emissive (strong colored fill). Satin, Lacquer, Ceramic, Enamel, Polished, and Classic smooth overlap with these or the preset materials and are omitted from the menu. Their stored descriptors and legacy surface-preset keys remain readable without visual migration; a saved personal material remains selectable. Ink and Toon retain their different brightness bands and emission. Material choices do not include a Look's lighting rig or contours.

Version-1, version-2, and version-3 looks remain readable; their saved focus/blur values are ignored when applying them as named looks. Version-2 atom/bond/surface slots migrate to the atom base material, applied everywhere; per-element and per-orbital material overrides are retired. Stored geometry, palette, and light intensities are preserved; the current camera stays unchanged. Missing rim direction and tone mapping values use their former defaults. Legacy flat material keys remain readable; the canonical rendering object takes precedence when present.

Looks preserve coordinates, topology, camera pose/projection and depth of field, visibility, selections, playback, orbital isovalues, Auto-iso, phase mapping, and surface/cloud mode. Camera/focus edits support Appearance Undo but do not mark a look Modified. Full presets, appearance autosave, and complete sessions retain camera/focus settings.

Camera clipping is derived from the visible rendered geometry, including atom radii, bond thickness, diffuse orbitals, and point/instanced clouds. Each side gets at least 3 Å of padding, increasing to 5% of the visible depth span for large structures. Bounds are cached and updated during rotation, zoom, playback, edits, and session restoration; fitting never computes hidden orbitals. Orthographic depth extends on both sides of the nominal camera position when needed, so large slabs remain complete without changing pose, magnification, or framing. Picking starts at the visible near plane, and depth-of-field uses the same signed depth range. Perspective clipping keeps a positive near plane and follows the visible geometry as the camera moves. These derived clipping limits are not saved style properties.

Studio **Colors → Orbital defaults** edits global colors; **Surfaces** edits global opacity. Each orbital independently inherits or overrides its colors and opacity. Sidebar/Object edits create explicit overrides; the scope status shows Style, Custom, or Mixed for each property group. **Use style colors** and **Use style opacity** clear the corresponding overrides for the current orbital/group. Studio **Apply defaults to all orbitals** clears both across all loaded layers. Undo restores the previous values and inheritance choices.

Saving, exporting, or setting a default look captures global defaults regardless of the selected orbital. Per-orbital overrides do not mark the shared recipe Modified, and survive changing or reverting a look. New sources inherit the current defaults. Session and recovery records preserve each layer's `styleOverrides` flags as well as its resolved appearance. Legacy sessions infer overrides from differences against the saved global defaults. The [scope audit](appearance-audit.md#style-studio-scope-audit) records the complete control mapping.

## Renderer contract

`appearance-model.js` validates and migrates geometry/material/color/light/effect data and creates Three.js materials. The shared material is independent of connector geometry. Vertex-colored surface emission remains an explicit descriptor value. Phase colors and field-gradient surface normals remain intact.

`bond-geometry.js` builds one closed cylinder for each straight bond component. Element coloring duplicates vertices at the color boundary while retaining continuous geometry and side normals; there are no internal midpoint caps. Kit's collars and curved shafts retain their geometric form, and live updates restore vertex colors when regenerating geometry.

Bond radius is a requested maximum. Each bond is capped against its smaller rendered atom, including multiple-component offsets, mesh facets, collars, and contours. End caps sit entirely inside the atom meshes. Requested settings remain portable; changes to atom size automatically update the effective bond thickness. See [bond fitting](bond-fitting.md) for the equations, limits, and hydrogen topology rules.

`appearance-looks.js` owns complete look recipes. `appearance-editor.js` binds native component controls. `looks-ui.js` manages the preview gallery, named look/material libraries, and appearance undo. `style-studio.js` handles the floating window, dragging, focus, and keyboard scope. Its controls share the sidebar's inspector styles; its shell uses the existing motion-panel/list-popover components. `app.js` applies component patches and synchronizes the existing renderer and scene model.

Material and light changes reuse existing geometry. Geometry, palette, and contour changes rebuild molecule display meshes only. Neither route re-marches orbital surfaces nor computes deferred Molden grids. Full looks also preserve existing orbital meshes. Cloud colors and opacity update from each layer's own appearance. Edit placement previews use the same material model.

Opacity edits also reuse surface/cloud materials and cached WBOIT pass materials. Alpha uniforms are initialized before shader compilation and shared by every side/lighting variant, so the first frame uses the selected opacity. Slider changes must not recreate materials or briefly render surfaces fully opaque. `looks.py` checks consecutive rendered frames and resource identity during drags, full-opacity transitions, and material changes.

The existing **Shadows** switch applies to atoms, bonds, and isosurfaces together, including orbital, arithmetic, phase-colored, and Bloch-colored surfaces. Surfaces cast onto the molecule and other surfaces and receive shadows from them. Emission and ambient/environment lighting remain visible in shaded regions. Hidden surfaces do not cast shadows. Cloud rendering keeps its existing behavior.

Shadows use a 2048 × 2048 map, capped at the device's texture limit, with PCF soft filtering. The shadow camera fits cached mesh bounds directly in light space, with padding for filtering, so elongated molecules use the available resolution efficiently. Its orientation follows the light rig, its center snaps to the texel grid, and depth/normal offsets scale with texel size to keep small contact shadows attached. These adjustments preserve the saved key-light direction and reuse existing geometry.

Transparent surface shadows approximate opacity using texel-scale coverage with PCF filtering; they are not refractive or colored transmission. WBOIT builds one complete shadow map before separating opaque and transparent color passes, then reuses it for those passes. Each alpha/beta viewport uses its own map, also when depth of field or standard transparency is active. The switch updates existing meshes without remeshing surfaces. Its portable key remains `molecule.feature.shadows`, so looks, presets, and sessions remain compatible. Owned surface depth materials are disposed with their meshes.

The automation API is `VibeMolAppearanceLooks.list/apply/applyColors/edit/material/snapshot/openStudio/closeStudio`. `snapshot()` returns `{styleRef, colorsRef, styleModified, colorsModified, label, settings, saved}`; it no longer returns a fused `activeLook`. `list()` marks experimental recipes. `apply` keeps colors by default; reference-render tools that need the original complete appearance pass `{includeColors:true}` explicitly. For example:

```js
VibeMolAppearanceLooks.apply('kit');
VibeMolAppearanceLooks.applyColors('opal');
// Restore an original complete combination, including colors:
VibeMolAppearanceLooks.apply('classic', { includeColors: true });
VibeMolAppearanceLooks.edit('material', { model: 'toon' });
VibeMolAppearanceLooks.edit('material', { roughness: 0.35 });
```

Validation: `make check`, `make test-unit`, and the `looks.py`, `premerge.py`, `sessions.py`, and `smoke.py` browser suites in `tests/e2e/`. Appearance regressions cover component independence, actual materials, shared materials across deferred orbitals and future sources, unchanged surface geometry, undo, named libraries, defaults, reload, malformed imports, and portable sessions.

`independent_colors` in `looks.py` checks both Studio and Properties: all seven Style selections preserve custom colors, all color schemes preserve material/geometry/lighting, sidebar/API scope agrees, explicit orbital overrides survive, and mixed combinations round-trip through saved looks and sessions. `look_tiles.py`, also run by `looks.py`, checks all seven complete tiles, reapplying the active style's colors, mixed-pair pressed state, Undo, saved-look selection, persistent Object overrides, exact copy, stationary hover, and keyboard focus. `look_references.py` checks per-axis dots/resets, labels, stable aliases, rename/update/delete, null/unlisted references, fresh-browser user baselines, startup defaults, legacy migration, and invalid-file atomicity. Unit tests cross-combine every built-in recipe without mutating either source and exercise deterministic reference migration.

`surface_shadows.py`, run by `looks.py`, compares rendered pixels with only the molecule or surface shadow draws suppressed. It verifies both directions of shadowing at opaque and translucent settings, actual alpha/beta shadow draw isolation, transparency fallback, phase/Bloch surfaces, visibility, unchanged geometry on toggles, and session restoration. It also checks that rotated/offset molecules and large surfaces remain inside the actual shadow camera, including pole-aligned lights, with tighter framing for elongated structures.

`style_studio.py` verifies the gallery, live edits, saving/export/reload, Undo/Revert, focus and shortcut isolation, dragging, matching typography, and light/dark/mobile layouts. It also checks both background controls, grouped color edits, rendered theme behavior, portable look/session restoration, appearance autosave, and unchanged surface geometry/deferred grids. Refresh the real-renderer thumbnails with `python tools/render_look_previews.py` (add `--software` for software WebGL). These previews use the same pyridine structure and camera for every current built-in preset.

`appearance_scopes.py` verifies shared sidebar/Studio editing and grouped Undo, camera isolation across every preset and legacy look imports, global surface-default capture, independent per-orbital overrides, explicit resets, future imports, session migration, and deferred-orbital groups.

`camera_depth.py` verifies a rotating 300-atom slab, zoom, Edit/Measure picking beyond the nominal camera plane, unchanged camera framing, session restoration, distant perspective views, diffuse 2C orbitals, transparency, depth-of-field, and point/instanced clouds.

## Color fill across geometry

The shared factory applies color-derived emission to element-colored bond vertices, instanced metal connectors, and phase-colored surfaces, just as it does to atom colors. Fixed-color fill and the fixed part of a mixed fill remain independent of element colors. Transparent WBOIT clones preserve this shader behavior. New Gel and Emissive recipes remove the legacy phase-surface emission suppression; explicitly saved legacy descriptors remain readable.

The affected default presets were Luminous Basic and Toon. Kit uses uniform bond colors by default, but benefits from the same correction when By element is enabled. Classic, Porcelain, Ink, and Opal have no emissive fill by default. Cylinder highlights naturally stretch along a bond even when its material is identical to a sphere's. `material_color_fill` in `tests/e2e/looks.py` compares actual GPU pixels across uniform, vertex, instance, and cloned materials for the entire menu, including fixed and mixed fill.
