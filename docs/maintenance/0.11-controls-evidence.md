# 0.11 controls: maintenance evidence, not a work queue

## Escape ownership

The merged#52 ladder expanded from300 to1248 pure-table cases, plus62 native
cases, to specify focus-owner and selection-state behavior correctly. The ten
`edit.perform` errors were causally repaired in the handler; matrix expansion
provides additional coverage. This case growth is a standing maintenance cost
for a hand-written ladder that partly overlaps platform facilities. Consider
`<dialog>`, `inert`, and focused-field-first ownership when evaluating0.11
controls. No ladder change or platform migration is scheduled here.

## Inter-surface placement

[#55](https://github.com/evangelistalab/vibemol/issues/55) is justified but not
scheduled. The strict guard already supplies clipped interactive rectangles,
DOM hit/stacking order, and checking across18 declared contexts/112 signatures.
This is the existing data/checking half of the policy, reducing the runtime work
relative to a from-scratch seven-requirement inventory. The runtime half must
use the model to place surfaces, with explicit lifecycle/ownership/no-fit rules.
Coverage remains incomplete.

The Floating UI trial is closed without execution. Its boolean `altBoundary`
selects clipping context; `shift()`/`flip()` do not supply arbitrary panel-obstacle
avoidance. Custom middleware would implement the deferred policy with an added
dependency. See the [placement audit](coordinates-placement-policy.md) for the
API source and closure rationale. No second surface or policy was converted.
