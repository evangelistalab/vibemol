# VibeMol 0.10.1

This bug-fix release follows the internal refactor in 0.10.0.

- **Saved appearance (#25):** restoration validates the complete saved payload before applying it and detects missing settings or references. A failed restore preserves the saved data, reports the failure in a persistent notice, and explains that autosave is paused.
- **Orthographic camera (#3):** camera and target changes refresh the derived frustum. This fixes the stale projection that produced a measured **1.56× zoom error**, including preset changes.
- **Video export (#11):** completing or stopping trajectory and vibration exports no longer reopens or leaves the crop-selection overlay active. A subsequent Save still opens a fresh crop selection.
- **Popover placement (#17, #53):** fixes the Metal popover's narrow-window bounds and overlap, and prevents the selection card from intercepting Coordinates Delete. These are specific repairs; a broader floating-surface placement policy remains deferred.
- **Escape handling (#52):** Escape follows an explicit priority order for focused fields, open surfaces and Edit actions, including focus return from the axis gizmo and repeated presses.
- **Input validation (#5):** unsupported or fractional atomic numbers are rejected before an import can replace the scene or alter topology. Valid Dummy atoms survive session round-trips.
- **Release channel (#77):** removes the retired beta flag, badge, version suffix and deployment workflow. The toolbar displays the same release version on every hostname.

The ordinary browser gate advances from **34 passing / 3 accepted failures / 37** at 0.10.0 to **37 passing / 0 failing / 37**. The accepted-failure set is intentionally empty; repaired exporter, Escape and Coordinates workflows must pass. Golden capture versions compare exactly, with no version-mapping exception.

The material-preset intermittent and the separately recorded unclassified harness findings remain open.
